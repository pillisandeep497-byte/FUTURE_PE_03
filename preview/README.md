# Preview — visual SEO content pack

`index.html` is a single-file, self-contained visual summary of the whole content pack.
It is what you screenshot for LinkedIn and what you open in front of a business owner.

**Open it:** double-click `index.html` — it works offline, no build step, no CDN.

## What it shows

| Section | What a viewer takes away |
|---|---|
| Why this shape | The three gaps the cluster exploits: published prices, an admitted limitation, capacity-gated publishing |
| Cluster architecture | Pillar + 5 supports drawn out, with the link rules stated |
| Intent mapping | Every keyword → one page → one intent → one funnel stage |
| The six articles | Each article's actual angle, not a generic description |
| Local SEO layer | Why the pillar is *not* a doorway page (the city-swap test) |
| Quality gate | QA score, findings fixed, and what still needs client confirmation |

## Images

`images/` holds six concept visuals referenced by the page. They are **AI-generated
placeholders**, not photographs of the real studio — the page says so in the footer.
Replace them with the client's own photos, or at least the three marked below, before
this goes live anywhere a prospect could mistake them for real work.

| File | Used for | Replace before publishing? |
|---|---|---|
| `keratin.jpg` | Pillar card | Yes — needs the client's finished-result photo |
| `comparison.jpg` | Cost card | No — generic illustration, but label it |
| `hair-salon-work.jpg` | Damage card | Yes — needs the client's actual process photo |
| `aftercare.jpg` | Aftercare card | No — product shot, generic |
| `storefront.jpg` | Local SEO card | **Yes, mandatory** — a storefront is a factual claim |
| `consultation.jpg` | Comparison card | Yes if the client has a real consultation photo |

Container-format and size details are in `images/README.md`.
